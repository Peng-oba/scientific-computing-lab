# 审查练习：这些报告能否支持“任务完成”

以下是人为设计的教学报告/候选建议，不是对你真实代码的诊断。先写“接受 / 否决 / 证据不足”和原因，再看后面的参考要点。不需要全部作为额外作业完成。

## 待判断内容

1. “测试命令返回 0，所以可以接受修改。”命令实际用了不存在的名称筛选，输出显示零个测试。
2. “源码已经改成 E=2000，但程序仍输出10，所以公式实现错了。”源码修改后没有重建，仍运行原有二进制。
3. “已解决回归失败：把误差容差从 1e-12 改成 100，全部测试通过。”没有给出任何误差或需求依据，demo 仍出现错误的第二次值。
4. “已充分测试应力：把被测函数当前输出存成 expected，再调用一次进行比较。”没有独立数学值、接口约定或外部基准。
5. “已修复释放后访问：delete 之后把 owner 指针设为 nullptr。”borrowed 仍然指向原地址，后续继续解引用它。
6. “两个 AI 都认为 OGS 调用图正确，所以可以直接放进作品集。”没有打开实际源码核对，也没有区分已运行与未运行内容。

给每条判断补一句：如果证据不足，我下一步只做哪个最小检查？

---

## 参考要点：先判断，再看

1. 否决“已验证”的结论。确认目标名称、实际选择数量，并用 --no-tests=error 阻止空测试被当作通过。
2. 证据不足以指认公式错误。先对正确 target 重建，再从明确路径运行，比较预期与实际。
3. 否决这种无依据的修复。恢复判据使已知故障暴露，随后修复实现；容差变化本身不是永远不允许，但必须有独立依据。
4. 不能作为充分正确性证据。这样的比较可能检查可重复性，但不能证明数学结果正确；需要独立预期或其他性质。
5. 否决。另一个指针不会因 owner 变量赋 nullptr 自动变得安全；核对访问发生时对象是否仍存活。
6. 证据不足。AI 复核可辅助导航，仍应打开实际入口、函数、断言，并如实记录运行范围。
