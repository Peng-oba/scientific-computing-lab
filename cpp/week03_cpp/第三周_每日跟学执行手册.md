### 3.3 每天都遵循同一协作顺序

1. **你先写：**预期行为、不能改变的条件、什么结果算失败。需要推导时可先独立写草稿，再让 AI 检查。
2. **agent 执行：**根据任务卡导航、写样板、运行命令；返回实际代码位置、命令、退出码和关键结果。

## 4. 全周贯穿的数学与接口约定

本周仍使用小型应力更新例子，以便把精力放在判断和验证上：

```cpp
struct MaterialState { double stress = 0.0; };
void updateStress(MaterialState& state, double modulus, double strain);
```

行为定义：

- 这是教学用一维线弹性关系：`stress = modulus * strain`。
- `strain` 是**总应变**。重复输入同一总应变，不应继续累加应力。
- `modulus` 必须有限且大于 0，`strain` 必须有限；负应变有效。
- 非法输入抛 `std::invalid_argument`，并保持调用前状态不变。
- 应力和模量采用相同应力单位，应变无量纲；本例可统一理解为 MPa。
- 本周数值均保证乘积可表示；参考实现不承诺全部极端浮点范围。

先独立完成下表，再与结果核对：

| 初始 stress | E | 总应变 | 调用方式 | 预期行为 |
|---:|---:|---:|---|---|
| 0 | 1000 | 0.01 | 一次 | 应力 10 |
| 7 | 1000 | 0 | 一次 | 应力 0，覆盖旧值 |
| 7 | -1000 | 0.01 | 一次 | 指定异常，状态仍为 7 |
| 0 | 1000 | 0.01 | 同样输入两次 | 两次均为 10 |

此约定只适用于教学函数。真实历史依赖材料模型的 trial/commit、损伤历史与路径效应要以其真实数学和软件约定为准，不能把这里的重复调用性质不加条件地套到整个 OGS 材料接口上。

### A. 你先完成测试设计

| 用例 | 必须检查的行为 | 容易漏掉什么 |
|---|---|---|
| normal | 1000×0.01 得到 10 | 只检查不崩溃，没有数值判据 |
| boundary | 从非零旧应力 7 更新到零应变，得到 0 | 若初始值取 0，可能漏掉没有覆盖旧状态的错误 |
| invalid | E=-1000 导致指定异常，原状态 7 不变 | 仅检查抛异常，不检查失败路径是否污染状态 |
| repeated | 同样总应变调用两次，结果仍为 10 | 单次调用可能看不出重复累加问题 |

参考值来自简单数学和明确接口约定，不能由“运行当前实现得到什么”反过来定义。即使另一个 AI 也给出相同结果，仍要能说明这个数学依据。

本例使用绝对容差 `1e-12`，针对这里的数值与单位。真实科学计算中可使用 `|a-b| ≤ atol + rtol×|b|` 等判据，atol 具有被比较量的单位，rtol 无量纲；具体数值要依据误差来源、量级与问题要求。本周只理解选择理由，不系统学习所有浮点误差理论。

### B. 你必须读懂的报告内容

| 故障 | 核心诊断 | 你要指出的事实 | 修复判断 |
|---|---|---|---|
| UAF | `heap-use-after-free` | borrowed 的访问位置、owner 的释放位置、原分配位置 | 借用访问发生时对象必须仍存活 |
| OOB | `heap-buffer-overflow` | 长度 3、无额外参数时 index=3、合法索引为 0/1/2 | 使用合法索引或在访问前验证边界 |
| 溢出 | `signed integer overflow` | int 最大值加 1，在哪种类型中先发生运算 | 在运算前检查范围或提升到能容纳结果的类型 |

本例 UAF 中给 owner 指针赋 nullptr 不会自动修复 borrowed；本例 OOB 中改用 vector 也不会自动使所有下标访问有边界检查；溢出发生后再转换类型不能撤销已经发生的 UB。

这三条解释比记忆完整报错模板更重要。内存地址和栈帧编号不用背。

最小修复可分别是：UAF 把访问移到释放前；OOB 明确读索引 2；溢出先做 `static_cast<long long>(maximum) + 1LL`。核对后让 agent 完成，不需要你从零手写三个程序。

修复前后应保留至少一个完整对照，其余两项也要读过真实报告并解释修复逻辑。时间允许可全部重跑；本例很小，工具正常时通常可在分配时段内完成。可预期的最小修复输出为 1、30，以及常见 32 位 int 环境下的 2147483648。

| 被测行为 | 实际调用函数、参数、返回或修改的状态 | 数学/接口约定是否支持 agent 的解释 |
| 断言与执行 | 断言、参考值、容差、选择方式、运行记录 | 真正检查了什么、漏了什么、是否确实运行目标用例 |

你必须打开至少三个位置：测试入口、被测函数、断言。agent 给出的路径与行号只是导航结果，不能自动当作内容已核实。

### C. 运行现有测试，先核对名称再选择

让 agent 对实际构建目录运行 `ctest -N`，检查已注册的名称，再使用实际名称筛选。CMake target、CTest 名称和 GoogleTest case 名称可能不同。

若 CTest 只注册了一个汇总程序，让 agent 用该程序的 `--gtest_list_tests` 列出 case，再用真实的 `--gtest_filter` 选择。报告必须包括实际选择数量，不能只写“测试通过”。

25 分钟内现有构建不可用，保存准确阻塞和下一步，不从零重建整个 OGS。此时可以完成源码追踪，但把“OGS 执行”保留为待补；小项目的结果不能冒充真实工程运行证据。

### D. 从真实约定提出一个补充测试

你先提出一个问题，例如：

- 某个已明确为“非法”的材料参数，是否确实走失败分支？
- 模型在已明确的纯弹性极限中，能否与独立解析值比较？
- 若接口明确区分 trial 与 accepted 状态，失败尝试是否应该保持 accepted 状态？

这些都是**候选问题**，不是对你现有模型的既定判断。先查数学定义、接口和调用约定，再决定哪个问题成立。本周不把“任意重复调用必须不变”强加到真实历史依赖材料模型，也不提前展开第 10 周的完整状态管理理论。

让 agent 给出一个最小测试方案：输入、预期来源、观察量、失败判据、需要的 fixture。你填写“接受/否决/证据不足”及原因。本周可把方案留在笔记中；只有现有条件明确且不超时才实际添加，不把新研究功能变成本周必做项。

### E. 可直接给 agent 的任务

> 在我给出的实际 OGS 仓库中，只读追踪一条与 ElasticIsotropicDamage 相关的已有测试。先报告当前版本和工作区状态，给出 target→测试入口→被测函数→断言的真实文件位置。测试不存在时明确说明并选择一个实际存在的替代项。已有构建可用时运行一个已确认名称的用例，记录选择数量、完整命令和结果；没有运行就写“未运行”。随后针对我提出的一个候选行为给出新增测试方案，先验证该行为是否符合模型约定。不要修改研究模型或通过更改参考值来消除失败。

### F. CI、日志、断言：只学与当前证据相关的部分

CI 可以自动重复已定义的构建与测试；它不会自动发现你的参考值来自错误假设。日志提供运行信息，但要选择能区分假设的变量。C/C++ `assert` 在定义 `NDEBUG` 时可能被移除，不能替代始终需要执行的输入校验；它与 GoogleTest 测试断言不是同一个机制。

根据本周真实遇到的问题，把 `notes/agent_working_rules.template.md` 补成十来条简短约定。可选择合并到练习仓库已有的 AGENTS.md，让后续任务复用构建路径、测试要求和报告方式；不要把模板直接覆盖已有项目规则。不要求安装新插件或学习配置体系。

**当天产出：**真实 OGS 路径记录、运行结果或明确阻塞、一个有依据的补充测试方案、简短协作约定。

**本人过关：**能指出一个断言覆盖的行为与没有覆盖的行为，并把“亲自核实”“AI 推测”“尚未运行”分开。若只得到一幅 AI 画出的调用图而未打开源码核对，该项未完成。

## 11. 第 7 天｜独立迁移、验收与复盘（45 分钟）

**当天学习重点：**判断你本人是否能把方法用于变化后的输入，并完整交代工作依据。

| 分钟 | 你和 agent 分别做什么 |
|---|---|
| 0–15 | 关闭 AI 的解释，自己预测新输入；可让 agent 按明确指令执行，或自己查速查表运行。 |
| 15–25 | 按实际证据做周验收，检查五项门槛，列出未完成项。 |
| 25–30 | 进行 2 分钟讲述，再用 3 分钟整理证据路径和补练项。 |
| 30–45 | 回答原计划五个复盘问题，每题约 3 分钟。 |

### A. 新输入迁移题：先写答案，后运行

在正确小项目中，只改变 demo 的初始值和输入：旧 stress=7、E=1500、总应变=-0.02，连续调用两次。**先不要让 AI 给答案。** 你写出：

1. 两次正确结果各是多少，为什么允许负应变？
2. 若存在错误累加，两次结果各是多少？
3. 哪个现有测试能发现累加问题，哪个行为此前尚未被单独测试？

然后让 agent 只改 `app/main.cpp` 的三个初始值，重建指定 target，运行并记录实际结果；不改函数实现或判据。核对后恢复这三处输入，再重建。

参考答案放在第 14 节。**答对数值但不能说明原因，只算部分掌握。** 命令忘了可以查；总量更新、状态覆盖和测试覆盖范围不能完全交给 AI 替你解释。

### B. 周验收：五项能力，每条证据 1 分，共 20 分

| 能力 | 四条计分依据 | 分数 |
|---|---|---:|
| 任务与预期 | 输入/单位/边界明确；状态语义明确；至少一个预期由自己先确定；修改范围与完成条件明确 | /4 |
| 版本与构建 | 审查并撤销明确改动；对应源码-target-产物；识别旧二进制；核对测试数量而非只看退出码 | /4 |
| 测试判断 | 三类输入覆盖；失败后状态被检查；同一回归红→绿；能否决无依据放宽容差 | /4 |
| 故障诊断 | 一个假设被实际证据否决；实际 debugger 观测；解释 UAF 三处位置；解释 OOB/UB 且有修复对照 | /4 |
| 迁移与交付 | 核对真实 OGS 路径；说明一个真实断言的来源和边界；交代版本/配置/未验证项；独立完成新输入解释 | /4 |

**建议 ≥16/20，并通过下面五项门槛，再进入下一周。** 这是本手册用于学习管理的建议，不是职业资格认证。

- [ ] 能从明确、干净的基线进行修改、测试、审查 diff，并安全撤销指定改动。
- [ ] 实际使用 debugger 定位一个小 bug；至少亲自重复一组关键观测。
- [ ] 能读懂 sanitizer 核心栈和相关生命周期/边界问题。
- [ ] 自己能给出预期，并证明同一测试在已知故障实现上失败、修复后通过。
- [ ] 不依赖 AI 解释，能完成新输入题并说清结论依据。

GoogleTest 或 OGS 若因环境原因未运行，必须保留待办；源码理解与小项目中已完成的能力可以分别计分，但不能声称完成了真实 OGS 运行验证。核心 debugger 门槛若未完成，则先用机动时间补齐。

### C. 2 分钟讲述模板

- 0–20 秒：任务的数学与接口约定；我需要验证什么。
- 20–45 秒：agent 承担哪些执行工作；我亲自确定了哪些预期。
- 45–80 秒：一条关键证据怎样排除了一个错误假设。
- 80–105 秒：修复、回归红→绿，以及我否决的一种假通过。
- 105–120 秒：OGS 迁移到了哪一步，哪些内容仍未验证。

只有实际完成后才可用于求职表述；教学项目不能包装成生产求解器交付经验。

### D. 原计划五个复盘问题

1. 本周最重要的一个概念是什么？
2. 哪一个问题我仍只能靠 AI/资料回答？
3. 我是否在真实代码中见过并使用了本周概念？
4. 本周产出能否在面试中用 2 分钟讲清楚？
5. 下周开始前，哪些内容只需查阅而不值得继续深挖？

## 12. 每天如何监测“我学会了”，而不只是“agent 做完了”

每天都把**任务完成状态**与**本人掌握程度**分开。可以出现“agent 已完成，但我解释不了”，也可以出现“我能解释源码，但本机工具还没跑通”。如实记录，才能正确补练。

每日四项，各 0–2 分：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 定义 | 没有预期，跟着 AI 结果改要求 | 提示后能写出预期或约束 | 先独立给出预期、边界和失败条件 |
| 核查 | 只读 AI 总结 | 查看了部分代码或日志 | 能把结论对应到真实 diff、路径、数量或原始报告 |
| 反证 | 不知道怎样让当前判断失败 | 按提示执行反例 | 能解释反例排除了什么、还有什么未排除 |
| 复述 | 只能照读答案 | 借助提示能说清 | 无 AI 解释时能独立说明因果与限制 |

**日过关建议：至少 6/8，且当天核心条件满足。** 已经掌握时，不要求反复手敲同一命令；如果某项为 0，针对它补一个最小动作后再打分。

每天的记录至少保留：

```text
任务目标与预期：
AI 实际执行了什么：
我亲自核对了什么：
原始证据在哪里：
接受 / 否决 / 证据不足，以及原因：
尚未运行或无法确认的内容：
```

最后补三行：今天理解了什么 / 哪里仍不清楚 / 下次要验证什么。不要写“学会了测试”，应写“我确认放宽到 100 的容差会把 10 的误差放过，不能接受这种修复”。

### 补练规则

| 卡点 | 限时补练 | 不再扩展什么 |
|---|---|---|
| Git 状态或撤销不清楚 | 在独立小项目重做一个文档提交与 revert，10–15 分钟 | 不学 Git 内部对象、复杂历史改写 |
| 不知道构建了什么 | 找到一个 source、target、产物，核对一次重建，15 分钟 | 不通读 OGS 全部 CMake 宏 |
| 测试全绿但不理解 | 保持用例，注入已知 bug，解释为什么红，15 分钟 | 不增加一批相同结构测试 |
| AI 修了多轮仍失败 | 回到最小复现，列一个假设和否决条件，15 分钟 | 不允许同时随意改算法、容差和输入 |
| 看不懂 sanitizer | 只找自己代码的访问/分配/释放三处，10–15 分钟 | 不背地址、shadow bytes 或全部运行时选项 |
| OGS 环境阻塞 | 记录版本、原始报错和下一步，完成源码核对 | 不从零重建全工程来“赶上进度” |

同一问题连续两次仍无进展，就携带最小复现与准确报错求助。机动时间用完则顺延对应项，不能删掉验收门槛来宣称通过。

## 13. 本周明确不要求学习的内容

- Git 参数大全、复杂 rebase 技巧和内部存储模型。
- 从空白背写大型 CMakeLists、复杂元编程和依赖管理体系。
- GoogleTest 宏目录、GDB 命令大全、所有 sanitizer 选项。
- 从零搭建 CI 平台、多 agent 编排、MCP 服务或插件体系。
- 把现有本构模型重写一遍、追加一个尚未验证的新物理机制。

相应内容遇到明确需求时查文档即可。你仍要保留理解代码所需的基础语义，特别是引用与生命周期、所有权、状态修改、异常路径和数值类型；它们决定你能否审查 AI 生成的实现。

## 14. 参考答案与自测要点：先做再看

| 问题 | 要点 |
|---|---|
| 命令退出码为 0，为何不一定完成任务？ | 命令可能没有执行目标测试，或运行对象不对应当前源码；还需核对范围与行为。 |
| 为什么 boundary 用旧应力 7 而不是 0？ | 非零旧状态能检查更新是否确实覆盖旧值，减少偶然通过。 |
| EXPECT_THROW 为什么不够？ | 抛异常前仍可能已经污染状态，需要检查失败后状态。 |
| AI 同时写实现与测试有什么检查重点？ | 防止两者共享同一错误假设；预期应有数学、接口或独立基准依据。 |
| 改到更大容差一定错吗？ | 不一定；若有量纲、误差来源和需求依据可以调整。本例从 1e-12 改到 100 没有依据且掩盖已知故障，所以否决。 |
| 让第二个 AI 审查算独立验证吗？ | 可提供另一份审查意见，但不能替代独立参考值和实际实验。 |
| 输入同样，总应变的重复更新应怎样？ | 在本教学契约中覆盖到同一应力；对历史材料模型必须先核对其具体接口与状态约定。 |
| sanitizer 不报错能否证明算法正确？ | 不能；只能讨论实际运行路径上相应检查的结果。 |
| 第 7 天正确输出？ | 1500×(-0.02)=-30，两次均为 -30；旧应力 7 被覆盖。 |
| 第 7 天若错误累加？ | 第一次 7-30=-23，第二次 -23-30=-53。 |
| 新输入扩展了什么检查？ | 负应变路径与非零旧状态下的正常更新；原 repeated 能抓累加，但原四例未单独覆盖负应变。 |
| 真实 OGS 测试名找不到怎么办？ | 报告搜索依据，选择实际存在的替代项并说明；不编造路径。 |

包内 `exercises/review_cases.md` 另有六条报告审查题及答案。无需六条全做：第 2 天选构建/测试两条，第 3 天选测试判据一条，第 5 或第 7 天选一条迁移检查，均计入既定时段。
