# 第三周｜AI 协作开发与证据核查速查

**修订版。** 日常命令可以交给 agent；本人要能解释预期、核查证据、判断改动是否满足任务。

| 环节 | 你先确定 | agent 可执行 | 你接受结果前看什么 |
|---|---|---|---|
| 定义 | 数学/接口约定、输入、范围、完成条件 | 复述需求、定位相关文件 | 预期有独立依据，歧义已解决 |
| 版本 | 当前基线、允许修改范围 | 状态、分支、差异、明确提交与撤销 | 实际 diff；未提交内容和撤销对象清楚 |
| 构建 | 目标和配置 | configure/build，分析编译链接报错 | source→target→产物；当前源码构建成功 |
| 测试 | 正常/边界/失败输入、容差和状态约束 | 写样板、执行、汇总 | 实际测试数量；同一用例红→绿；判据没有被无依据放宽 |
| 诊断 | 最小复现、假设与否决条件 | 断点、变量、调用栈、sanitizer | 原始证据是否支持根因；至少一条替代解释被排除 |
| 交付 | 接受/否决/证据不足 | 整理命令与结果 | 版本、路径、结果、限制可复现，未知项如实保留 |

**任务卡六项：**目标 / 相关上下文 / 行为约定 / 允许修改 / 完成条件 / 证据要求。

**正确基线（在 project 根目录）：**

```bash
cmake -S . -B build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build/debug --parallel 2
ctest --test-dir build/debug --output-on-failure --no-tests=error
./build/debug/material_demo
```

普通模式 4/4、demo 为 10/10；GoogleTest 单独构建目录是 8 个。`ctest -N` 不执行测试；筛空测试不能计为验证。构建失败时不能拿旧程序证明新源码正确。

**Git 核查：**`git status --short`、`git diff`、暂存后 `git diff --cached`、`git log --oneline -3`。干净状态下对明确提交做 revert，检查反向提交和保留内容。已有仓库不嵌套初始化。

**Debug 核查：**`break` / `print` / `bt` / `watch -l` / `step` / `next`。先核对二进制，再看两次输入与旧、新状态。源码猜测不能冒充动态观测。

**sanitizer 核查：**使用独立 `build/sanitize`、`-DLAB_ENABLE_SANITIZERS=ON`，显式构建并分别运行 fault_uaf、fault_oob、fault_overflow。报告先看类型、自有代码访问位置，再看分配/释放或非法操作。故障样例预期非零；修复后重建重跑。

**三种不能接受的“通过”：**零个目标测试；运行旧产物；无依据放宽容差使错误实现通过。另一个 AI 的赞同不代替数学依据和运行结果。

**停止线：**会用、能核查即停止重复语法训练。每天留预期、实际证据、本人判断与未验证项；收尾用自己的话解释一条因果关系。
