### 先校正三个容易学偏的地方

1. **const& 不能用来直接更新传入对象的普通成员。** 原计划要求比较四种 updateState 接口，其中 const& 版本应读取旧状态并返回新对象。不能为了凑齐四种形式使用 const_cast。
2. **const& 不是所有参数的默认最优选择。** 例如 double 这类小型输入通常按值传递即可；对复制代价较大的只读对象，const& 常有意义。性能优劣最终需要测量。[C++ Core Guidelines：F.16、F.17](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rf-in)
3. **指针/引用的类型本身通常不足以证明谁负责资源释放。** 现代接口常用裸指针/引用表达借用，但阅读现有代码仍需核对创建、存储和销毁位置。[C++ Core Guidelines：R.3、R.4](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rr-ptr)

### 必须理解的语义表

下面假设调用时传入类型匹配的、仍然存活的普通对象。若按值传递类对象，传入左值通常调用复制构造；临时量、移动和复制消除会影响实际构造过程，不要推广成“按值永远恰好复制一次”。

| 形式 | 对本实验意味着什么 | 能否通过形参修改原对象 | 需要防范什么 |
|---|---|---|---|
| T x | 初始化一个独立的形参对象 | 对 double 的形参赋值不会修改调用方 | 大对象复制成本；若 T 内部持有指针，复制 T 不一定复制其指向资源 |
| T& x | x 是传入对象的别名 | 可以 | 被引用对象必须仍存活；引用本身不负责延长一般对象寿命 |
| T const& x | 通过只读访问路径借用对象 | 不能直接修改普通成员 | 只读访问不等于全局不变；不能据此断言返回引用安全 |
| T* x | 形参保存一个地址值副本 | 有效时可通过 *x 修改 | nullptr、悬空、越界；地址值不自动证明所有权 |

引用绑定后不能改绑到另一个对象：r=b 是给 r 原先引用的对象赋值。普通指针可以被重新赋值。声明中的 & 与表达式中的 & 不同：T& r 是引用声明，&x 是取地址；T* p 是指针声明，*p 是解引用。

### 动手任务 A：自己补上四个函数体

```cpp
double byValue(double x);          // 把局部 x 设为 2，返回 x
void byRef(double& x);             // 把原对象设为 2
double byConstRef(double const& x);// 返回 x+1，不修改 x
bool byPointer(double* x);         // 空指针返回 false；否则写 2 并返回 true
```

每次调用前都执行 double x=1.0；不要依次使用已经被上一个函数修改的 x。记录如下结果：

| 调用 | 调用后的 x | 返回值 | 原因 |
|---|---:|---|---|
| byValue(x) | 1 | 2 | 修改的是形参对象 |
| byRef(x) | 2 | 无 | 通过别名写原对象 |
| byConstRef(x) | 1 | 2 | 返回计算结果，输入保持不变 |
| byPointer(&x) | 2 | true | 通过地址写原对象 |
| byPointer(nullptr) | 不涉及 x | false | 按本练习约定处理空输入 |

如需观察对象身份，可以比较地址或打印地址；只判断同一时刻两个访问路径是否对应同一个对象，不记录某个固定十六进制地址作为答案。

### 动手任务 B：为什么函数里改 p 没改到外面的 p

```cpp
void rebind(double* p, double* other) {
    p = other;
    *p = 9.0;
}

double a = 1.0, b = 2.0;
double* p = &a;
rebind(p, &b);
```

先预测 a、b 和 p 的指向，再运行。正确结果：a=1，b=9，调用方 p 仍指向 a。解释必须包含“p 形参是地址值的副本”。T*& 和 T** 能用于改变调用方指针，但本周只需知道存在，不展开二级指针练习。

### 当天自测与通过条件

1. 按值传入 double 后修改形参，调用方会变吗？为什么？
  不会. 按值传递时, 函数在自己的栈帧上创建一份独立的副本，形参和实参是两块不同的内存.
  修改形参只改副本, 函数返回时副本销毁, 调用方的原对象完全不受影响.
2. 声明 double& r=a; 后执行 r=b;，r 是否改为引用 b？
  不是. 引用一旦绑定就无法改绑. r = b; 不是让 r 改为引用 b, 而是把 b 的值赋给 r 所引用的对象 a.
  执行后 a 的值变成 b 的值, 但 r 仍然引用 a.
3. 把 nullptr 传给指针函数与解引用 nullptr 是同一件事吗？
  不是. 这是两个完全不同的操作, 一个是合法的 (传参), 一个是 UB (解引用).
4. rebind 示例中为什么 b 变了而调用方 p 没变？
  这里同样是按值传递, 此时会创建一个指针副本 p_copy, p_copy 存储的地址指向 b,
  所以通过解引用 p_copy 会修正 b, 但本身不会影响调用方 p.
  rebind 的 p 是按值传递的副本: p = other 只改副本的指向 (main 的 p 不变),
  但 *p = 9.0 改的是副本指向的共享对象 (b 变了).

**通过条件：** 四题全部解释正确，五个函数调用结果符合表格。若第 2 或第 4 题错误，用 a、b、形参 p 三个标签重新做一次，不追加学习其他指针语法。

### 四个概念用这张表区分

| 概念 | 本周需要的含义 | 示例 |
|---|---|---|
| scope：作用域 | 源码中名字可以被查找到的范围 | 局部变量的名字在离开代码块后通常不可见 |
| lifetime：生命周期 | 某个具体对象已开始存在、尚未结束存在的时间区间 | delete p 后，原动态对象已结束生命，局部 p 这个名字仍可能可见 |
| automatic storage | 普通局部对象通常随相应代码块退出而销毁 | 函数内部的 double x |
| dynamic storage | 动态获得的存储由对应管理逻辑释放 | new 得到的对象不会因保存地址的局部指针离开作用域而自动释放 |

stack/heap 是常用实现层说法；C++ 语言层还区分静态和线程存储期，且不要求普通局部变量一定出现在物理栈内存中。本周只要能说明“局部 Eigen::VectorXd 对象”和“它管理的动态系数存储”并非同一个层次，不必研究内存布局。[C++ 工作草案：对象生命周期](https://eel.is/c++draft/basic.life)

### 观察实验：先看顺序，不背构造函数语法

### 错误 A：返回局部对象引用

```cpp
double const& badReference() {
    double local = 3.0;
    return local;
}
// 调用者若通过返回的引用读取 local，访问已结束生命的对象。
```

圈出 return local：它没有把 local 变成长期对象；函数离开时 local 的生命结束。返回类型里的 const 只限制访问权限，不提供寿命保证。修复为按值返回 double；不能通过在调用方再加 const& 挽救已经悬空的引用。

这个错误先做代码判断即可。可以编译看警告，但不要期待“每个编译器都必须报同一句警告”；编译成功也不代表有效。

### 错误 B：释放后继续使用

```cpp
double* p = new double(3.0);
double* alias = p;
delete p;
p = nullptr;
// double y = *alias;  // 若执行，访问已经释放的对象：未定义行为。
```

圈出 delete p：对象已经销毁；随后给 p 置空，不会修改 alias，也不会使原对象复活。优先修复为不需要动态分配的局部对象，并让所有访问在它的生命周期内完成。若实际任务确需动态资源，所有权设计放在第 2 周继续。

本练习的正确答案是“若执行该读取则发生未定义行为”，不是“一定崩溃”或“必然读出随机数”。不通过反复运行收集所谓正确输出。

### const 的最小完整对照

以下都以普通 double 或没有特殊 mutable 成员的简单状态对象为例。

| 声明 | 是否能经该名字修改目标值 | 是否能改为指向/引用另一对象 |
|---|---|---|
| double const x=1.0 | 不能改 x | 不涉及指向关系 |
| double const& r=a | 不能经 r 改 a | 引用不能改绑 |
| double const* p=&a | 不能经 *p 改 a | 可以给 p 赋另一个地址 |
| double* const p=&a | 可以经 *p 改 a | 不能给 p 赋另一个地址 |
| double const* const p=&a | 不能经 *p 改 a | 不能给 p 赋另一个地址 |

const double& 与 double const& 在这里同义。const 指针不是精确到足以消除歧义的说法，应说明“指针自身不可改”还是“经指针只读目标”。

### 8 项编译实验

先准备 double a=1.0,b=2.0;，以及下面三个指针：

```cpp
double const* p = &a;
double* const q = &a;
double const* const z = &a;
double const& r = a;
```

各测试项使用独立的新程序或每次恢复同一初始条件。预期失败的语句一次只解除一条注释；不要把多条失败混在一起。可用 g++ -std=c++17 -Wall -Wextra -pedantic -fsyntax-only const_case.cpp，只做编译检查。

| 编号 | 待判断语句 | 预期 | 解释 |
|---|---|---|---|
| C1 | p=&b; | 编译通过 | p 自身不是 const |
| C2 | *p=3.0; | 编译失败 | 经 p 只能读目标 |
| C3 | *q=3.0; | 编译通过 | q 固定指向，但目标可写 |
| C4 | q=&b; | 编译失败 | q 自身不可赋新地址 |
| C5 | z=&b; | 编译失败 | z 自身不可改 |
| C6 | *z=3.0; | 编译失败 | 经 z 目标不可写 |
| C7 | r=3.0; | 编译失败 | 不能经只读引用赋值 |
| C8 | a=4.0; 然后读取 r | 编译通过，r 读到 4 | a 自身可修改，r 没把 a 全局冻结 |

**关键自查：** 如果你把 C8 判错，说明把 const 访问路径误解成全局不可变了。指针成员、mutable 成员、线程安全等边界本周只知道存在；不展开 const_cast 练习。

### 临时对象：只掌握两个对照

### 先写清教学数据，避免把语义实验当成材料模型

```cpp
struct MaterialState {
    double damage = 0.1;
    double kappa = 0.2;
    Eigen::VectorXd stress = Eigen::VectorXd::Ones(3);
};
```

本程序的三分量 stress 是便于看结果的教学向量，不规定 OGS 的应力分量数、Voigt/Kelvin 映射或物理单位。下面规则也不是你的统计损伤本构方程：

```text
delta = 0.1
damage_new = damage_old + delta
kappa_new  = kappa_old  + 2*delta
stress_new = 2*stress_old
```

因此一次更新应得到 damage=0.2、kappa=0.4、stress=(2,2,2)。规则刻意固定，只检验对象是否正确复制和修改，不讨论损伤不可逆、应力积分或切线。

### 需要自己实现的四个接口

```cpp
void updateByValue(MaterialState state, double delta);
void updateByReference(MaterialState& state, double delta);
MaterialState updateByConstReference(MaterialState const& state, double delta);
bool updateByPointer(MaterialState* state, double delta);
```

第一版按值函数在内部更新并打印局部结果，但不返回新状态，便于观察更新为何没有传出去。第二版修改借用的原对象。第三版先从输入复制出局部 result，对 result 更新，再按值返回；调用方显式接收结果。第四版先处理 nullptr，再更新有效对象。

这里 const& 版本内部仍有显式复制，因为它需要生成独立结果。因此不能从参数写了 const& 推断“整个函数没有复制”。同理，按值接口也可能是合理设计；本实验只是用未返回结果的版本展示状态更新丢失这一错误用法。

### 六个必做实验及明确答案

每个案例从全新的 MaterialState 初值开始；只比较一次更新。浮点判断使用绝对误差 1e-12，这个量级仅适用于本教学小数运算，不作为实际仿真的统一容差。

| 实验 | 具体操作 | 必须观察到的结果 |
|---|---|---|
| M1 按值 | updateByValue(original,0.1) | 函数内部为 0.2、0.4、(2,2,2)；original 仍为初值 |
| M2 引用 | updateByReference(original,0.1) | original 变为 0.2、0.4、(2,2,2) |
| M3 const& | auto next=updateByConstReference(original,0.1) | original 保持初值，next 为更新值 |
| M4 有效指针 | updateByPointer(&original,0.1) | 返回 true，original 为更新值 |
| M5 空指针 | updateByPointer(nullptr,0.1) | 返回 false，不解引用、不访问对象 |
| M6 向量复制独立性 | MaterialState copy=original; 然后 copy.stress[0]=9.0 | original.stress[0] 仍为 1，copy.stress[0] 为 9 |

对这个包含标量和拥有自身数据的 Eigen::VectorXd 的结构，正常复制会得到独立的向量值；不要把结论推广到包含裸指针、Eigen::Map、Eigen::Ref 或其他视图的任意结构体。Eigen 动态向量的类型与初始化可查：[Eigen：The Matrix class](https://libeigen.gitlab.io/eigen/docs-nightly/group__TutorialMatrixClass.html)。

### 十道闭卷题

1. f(double x) 中给 x 赋值，能修改调用方的 double 吗？
  不能. double x 是按值传递, 实际修改的是函数创建的副本
2. double& r=a; r=b; 后，r 引用的是谁？
  r 引用的是 a. r=b 是给 a 赋值, 不改变引用绑定对象
3. 返回普通局部变量的 const&，为什么不安全？
  函数结束时, 局部对象销毁, const& 不会延长局部对象声明周期
4. T const* p 与 T* const p 分别限制谁？
  第一处 const 修饰 T, 即 无法通过 *p 修改值, 但可以改变 p 指向的地址
  第二处 const 修饰 *, 即 无法改变 p 指向的地址, 但可以通过 *p 修改值
5. 函数形参 T* p 在内部改为另一个地址，调用方的指针一定跟着改吗？
  不一定. 对普通 T* 按值形参重新赋地址不会修改调用方指针
6. update(MaterialState const& s) 能否直接写 s.damage？若要求更新后返回结果，应怎样设计？
  不能. 可以在函数内部进行拷贝操作, 如 MaterialState r = s; 然后更新 r 并返回
7. const 引用是否使一个原本非 const 的对象在所有访问路径上都不能改？
  不是. 其他合法的可写访问路径仍可修改原本非 const 的对象
8. scope 与 lifetime 有何不同？给一个来自第 2 天的反例。
  scope 表示作用域; lifetime 表示声明周期
  ```cpp
  int *p = nullptr;
  {
    int local = 42;
    *p = &local;
  }
  // p 的 scope 还在, 但 p 指向的 local 的声明周期已经结束 
  ```
9. 对本周 MaterialState trial=accepted 的对象初始化和 MaterialState& trial=accepted 有何关键区别？
  MaterialState，trial=accepted 实现了拷贝构造, trial 和 accepted 位于两个独立的栈内存, 相互之间没有影响
  MaterialState& trial=accepted 为引用, trial 是 accepted 的别名
10. 说出 S01-S10 中一条真实声明，解释权限与寿命判断，并指出证据位置。
